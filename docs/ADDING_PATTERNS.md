# 項目を追加する手順

## 作業の単位

通常は未着手の1〜3項目を選ぶ。docs/BACKLOG.mdで担当する項目を「作業中」にし、他の作業と衝突していないことを確認する。1項目を説明・デモ・指示文・検証まで完了させてから、次へ進む。

## 実装

1. 既存の名前・別名・用途・デモの挙動と重複しないか確認する。
2. 公式ドキュメントなどの一次資料を確認する。設計上の提案を、必ず効果があるという事実として書かない。
3. src/catalog/patternsに英語IDのJSONを作る。既存項目のフィールドに揃え、参考URLと確認日を入れる。
4. src/types.tsのDEMO_IDSにIDを登録し、src/demos/Demos.tsxに対応する操作デモを追加する。
5. src/components/Thumbnail.tsxにプレビューを追加する。一覧・検索画面に個別の項目をハードコードしない。
6. 設定の選択肢には、デモで使うvalue・表示用label・指示文用promptValueを用意する。promptの `{{controlId}}` と一致させる。
7.関連項目は実在するIDを指定する。個人情報や外部アカウントへの書き込みをデモに使わない。

## 検証と掲載

```powershell
npm.cmd check
npm.cmd test
npm.cmd run build
npm.cmd run dev
```

- デモが固有の挙動を持ち、説明・指示文・現在の設定と一致する。
- 設定変更でデモが切り替わり、リセットできる。
- 日本語・英語・別名で検索できる。
- 狭い表示幅でも横にはみ出さず、操作できる。
- キーボードと、動きを減らす設定に対応する。
- ダイアログは開いている間のフォーカス・Esc・閉じた後の戻り先を確認する。
- 不明な設定値や関連IDはチェックで検出する。
- 指示文のコピーができ、失敗時にも手動でコピーできる。

確認後にverifiedAtを更新し、バックログを完了にする。PROGRESS.mdに確認した内容と未確認の範囲を記録する。mainへのpush後、GitHub Actionsと公開URLの結果を確認してから「公開済み」と報告する。

## 余剰枠での追加について

この手順はCodex / Claude Codeのどちらでも使える。現時点では手動依頼による追加用であり、利用枠の監視や定期実行を設定したものではない。

将来は作業開始前に残枠・予約枠・観測時刻・実行上限を確認する。取得できない、古い、主要作業向けの枠が不足する場合は開始しない。担当候補がない場合は水増ししない。途中で止まったら「作業中」の項目と次の操作を残す。
